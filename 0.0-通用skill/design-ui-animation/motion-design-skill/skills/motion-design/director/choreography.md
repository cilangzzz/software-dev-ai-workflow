# Choreography (编排)

## 多元素协调原则

### 1. 主角先行

在多元素场景中，主角元素首先或最突出地入场。

**原因**：引导用户注意力，建立视觉层次。

**实现**：
- 主角最先开始运动
- 或主角运动幅度最大
- 或主角使用最强烈的缓动

### 2. 空间一致性

所有元素应从相同方向入场。

**原因**：保持空间连贯性，避免混乱。

**方向语义**：
| 方向 | 含义 |
|------|------|
| 从下方 | 到达、出现 |
| 从右侧 | 前进、下一个 |
| 从左侧 | 返回、上一个 |
| 从上方 | 下拉、权威 |

### 3. 反向运动

主角向一个方向移动时，环境向相反方向轻微移动。

**比例**：环境移动速度 = 主角移动速度的20-30%

**效果**：增加深度感，强化主角运动。

## 1/3 规则

### 距离规则

**规则**：没有动画在没有关键帧变化的情况下超过屏幕的1/3。

**原因**：超过此距离，用户开始失去对运动轨迹的跟踪。

**解决方案**：
- 添加中间关键帧
- 分阶段运动（先到一个位置，再继续）
- 使用淡入淡出过渡

### 元素规则

**规则**：有3+元素时，同时运动的元素不超过1/3。

**原因**：太多同时运动会分散注意力，失去焦点。

**解决方案**：
- 交错入场（stagger）
- 分组运动
- 主次分离

## 交错策略 (Stagger)

### 交错预算表

| 模式 | 延迟 | 总预算 | 用例 |
|------|------|--------|------|
| 微级联 | 20-40ms | <200ms | 列表项、网格单元格 |
| 标准 | 50-100ms | <400ms | 卡片、面板、导航 |
| 戏剧性 | 100-200ms | <600ms | 主角区块 |
| 波浪 | 30-60ms | <500ms | 数据可视化 |

**关键**：总交错时间必须保持在500ms以下。

### 交错模式

#### 线性交错

每个元素等距延迟。

```javascript
// 示例：每项延迟50ms
stagger: 50 // ms
```

#### 中心扩展

从中心元素开始，向两端扩散。

```javascript
stagger: {
  each: 50,
  from: "center"
}
```

#### 随机交错

元素以随机顺序入场。

```javascript
stagger: {
  each: 50,
  from: "random"
}
```

## 分阶段策略 (Staging)

### 焦点转移

1. 淡化非焦点元素（透明度40-60%）
2. 可选：添加轻微模糊（2-4px）
3. 主角入场
4. 主角稳定后恢复其他元素

### 层次编排

```
时间线:
0ms    -----> [主角开始]
100ms  -----> [次要元素开始]
200ms  -----> [环境层开始]
300ms  -----> [主角稳定]
400ms  -----> [全部完成]
```

## 完整编排示例

### 仪表板入场

```
阶段1 (0-300ms): 主角图表
  - 从下方滑入（350ms, ease-out）
  - 阴影跟进（50ms延迟）

阶段2 (100-400ms): 统计卡片
  - 交错入场（50ms间隔）
  - 每张卡片200ms
  - 从左侧滑入

阶段3 (300-500ms): 侧边栏
  - 淡入 + 轻微位移
  - 较低视觉权重

环境层 (全程):
  - 背景渐变缓慢脉动
  - 装饰元素微动
```

### 表单错误显示

```
阶段1 (0-200ms): 抖动
  - 整个表单轻微抖动（300ms）
  - 或仅问题字段抖动

阶段2 (100-300ms): 错误消息
  - 滑入下方（200ms）
  - 红色边框高亮

阶段3 (200-400ms): 其他字段
  - 非问题字段变暗
  - 问题字段放大强调

环境层:
  - 背景轻微变红调
```

## 编排检查清单

- [ ] 是否有明确的主角元素？
- [ ] 入场方向是否一致？
- [ ] 是否应用了1/3规则？
- [ ] 交错总时间是否<500ms？
- [ ] 是否有次要和环境层？
- [ ] 焦点是否清晰？
- [ ] 运动是否感觉协调而非混乱？
