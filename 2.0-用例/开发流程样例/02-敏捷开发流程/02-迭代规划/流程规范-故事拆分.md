# 流程规范：故事拆分

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 故事拆分 |
| 所属阶段 | 迭代规划阶段 |
| 流程负责人 | 敏捷团队 |
| 前置流程 | 需求梳理 |
| 后置流程 | 任务分配 |

## 流程目的

将过大的用户故事（Epic）拆分为符合INVEST原则的小故事，确保每个故事可以在一个迭代内完成。

## 触发条件

- 用户故事过大（Story Point > 8或13）
- 用户故事无法在一个迭代内完成
- 用户故事估算不确定

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 过大的用户故事 | Product Backlog | 必须 |
| 业务规则 | 产品负责人 | 必须 |
| 验收标准 | 需求梳理 | 建议 |

## 执行步骤

### Step 1: 故事评估

- [ ] 识别过大的用户故事（Epic）
- [ ] 分析故事复杂度来源
- [ ] 确认故事拆分必要性
- [ ] 选择拆分策略

### Step 2: 拆分策略选择

根据故事特点选择合适的拆分策略：

#### 按业务流程拆分

- [ ] 识别业务流程步骤
- [ ] 为每个步骤创建独立故事
- [ ] 确保每个故事有独立价值

#### 按用户角色拆分

- [ ] 识别故事涉及的用户角色
- [ ] 为每个角色创建独立故事
- [ ] 确保故事覆盖所有角色需求

#### 按功能点拆分

- [ ] 识别故事包含的功能点
- [ ] 为核心功能创建独立故事
- [ ] 为扩展功能创建后续故事

#### 按复杂度拆分

- [ ] 识别简单实现和复杂实现
- [ ] 先创建简单版本故事
- [ ] 再创建增强版本故事

#### 按数据范围拆分

- [ ] 识别故事涉及的数据范围
- [ ] 为不同数据范围创建独立故事
- [ ] 确保数据完整性

### Step 3: 故事拆分执行

- [ ] 应用选定的拆分策略
- [ ] 创建拆分后的用户故事
- [ ] 为每个故事编写验收标准
- [ ] 确保故事符合INVEST原则

### Step 4: 故事验证

- [ ] 验证故事独立性
- [ ] 验证故事可估算
- [ ] 验证故事可在一个迭代内完成
- [ ] 验证故事有独立价值

### Step 5: 更新Backlog

- [ ] 将拆分后的故事添加到Product Backlog
- [ ] 调整故事优先级
- [ ] 移除原Epic故事
- [ ] 记录拆分关系

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 拆分后的用户故事 | 文档/工具 | 项目管理工具 |
| 验收标准（更新） | 文档/工具 | 项目管理工具 |
| Story Point估算（更新） | 文档/工具 | 项目管理工具 |

## 质量标准

- 拆分后的故事符合INVEST原则
- 每个故事Story Point <= 8（或团队约定值）
- 拆分后故事可独立开发和测试
- 验收标准清晰可测试

| Skill | 用途 |
|-------|------|
| user-story-generator | 用户故事生成和拆分 |
| requirement-analyzer | 需求分析 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 无法找到合适的拆分点 | 考虑技术拆分或创建Spike |
| 拆分后故事仍过大 | 继续拆分或延长迭代周期 |
| 拆分导致故事价值不完整 | 重新评估拆分策略 |
| 依赖关系复杂 | 先拆分依赖项，再拆分主故事 |

## 故事拆分模式

| 模式 | 适用场景 | 示例 |
|------|---------|------|
| 按流程 | 多步骤业务流程 | 用户注册 → 验证 → 激活 |
| 按角色 | 多角色场景 | 管理员审核、用户提交 |
| 按功能 | 功能复杂故事 | 基础搜索 → 高级搜索 |
| 按复杂度 | 简单到复杂递进 | 简单报表 → 复杂报表 |
| 按数据 | 数据范围大 | 单条数据处理 → 批量处理 |

## INVEST原则检查

| 原则 | 检查项 |
|------|--------|
| Independent | 故事之间是否相互独立？ |
| Negotiable | 故事内容是否可协商？ |
| Valuable | 故事是否有独立价值？ |
| Estimable | 故事是否可估算？ |
| Small | 故事是否足够小？ |
| Testable | 故事是否有明确的验收标准？ |

## Spike故事

当无法确定如何拆分时，可以创建Spike故事：

| 属性 | 说明 |
|------|------|
| 目的 | 探索技术可行性或需求细节 |
| 时间盒 | 通常限制在半天到一天 |
| 产出 | 知识、原型或拆分建议 |
| 不交付 | Spike本身不交付产品增量 |
