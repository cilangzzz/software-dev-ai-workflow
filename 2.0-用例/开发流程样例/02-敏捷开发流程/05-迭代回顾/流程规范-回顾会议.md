# 流程规范：回顾会议

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 回顾会议 |
| 所属阶段 | 迭代回顾 |
| 流程负责人 | Scrum Master |
| 前置流程 | 迭代评审 |
| 后置流程 | 改进项识别 |
| 建议时长 | 60分钟（2周迭代） |

## 流程目的

通过结构化的回顾会议，让团队反思迭代过程，识别改进机会，促进持续改进。

## 触发条件

- 迭代评审会议结束
- 全体团队成员可参加
- 迭代周期结束前

## 参与人员

| 角色 | 必须 | 说明 |
|------|------|------|
| Scrum Master | 是 | 会议主持人 |
| 开发团队 | 是 | 全员参与 |
| 产品负责人 | 建议 | 可选择性参与 |
| 利益相关者 | 否 | 通常不参与 |

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 迭代目标 | 迭代规划 | 必须 |
| 迭代度量数据 | 敏捷度量体系 | 建议 |
| 上迭代Action Items | 上次回顾 | 必须 |
| 团队情绪记录 | 日常收集 | 可选 |

## 执行步骤

### Step 1: 会议准备（会前）

- [ ] 确认会议室和时间
- [ ] 收集迭代度量数据
- [ ] 准备回顾模板
- [ ] 回顾上迭代Action Items状态
- [ ] 设置安全环境氛围

### Step 2: 开场热身（5分钟）

- [ ] 欢迎参与者
- [ ] 说明会议目的和规则
- [ ] 强调"对事不对人"原则
- [ ] 检查上迭代改进项完成情况

### Step 3: 数据收集（10分钟）

- [ ] 展示迭代度量数据
- [ ] 回顾迭代目标和完成情况
- [ ] 收集团队观察和感受
- [ ] 使用时间线或事件回顾

### Step 4: 分析讨论（25分钟）

根据选择的回顾格式进行：

#### 格式一：Start-Stop-Continue

| 分类 | 问题 | 时间 |
|------|------|------|
| Start | 下迭代应该开始做什么？ | 8min |
| Stop | 下迭代应该停止做什么？ | 8min |
| Continue | 哪些做得好应该继续？ | 9min |

#### 格式二：4Ls

| 分类 | 问题 | 时间 |
|------|------|------|
| Liked | 喜欢什么？ | 6min |
| Learned | 学到了什么？ | 6min |
| Lacked | 缺少什么？ | 6min |
| Longed for | 期待什么？ | 7min |

#### 格式三：Mad-Sad-Glad

| 分类 | 问题 | 时间 |
|------|------|------|
| Mad | 什么让你生气？ | 8min |
| Sad | 什么让你难过？ | 8min |
| Glad | 什么让你高兴？ | 9min |

### Step 5: 识别改进项（15分钟）

- [ ] 汇总讨论结果
- [ ] 识别主要改进项
- [ ] 投票确定优先级（每人3票）
- [ ] 选择Top 3改进项进入下迭代

### Step 6: 制定Action Items（5分钟）

- [ ] 为每个改进项制定具体行动
- [ ] 确定负责人和截止时间
- [ ] 明确完成标准

### Step 7: 结束总结

- [ ] 感谢团队参与
- [ ] 确认Action Items
- [ ] 收集会议反馈
- [ ] 发布回顾报告

## 回顾格式选择指南

| 格式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| Start-Stop-Continue | 快速回顾，问题明确 | 简单直接，易于执行 | 深度不足 |
| 4Ls | 深度反思，学习型团队 | 促进学习，内容丰富 | 需要较多时间 |
| Mad-Sad-Glad | 情绪问题，团队冲突 | 关注情绪，促进沟通 | 可能过于负面 |
| Sailboat | 长期项目，进展评估 | 视觉化，全局视角 | 需要较多准备 |
| Timeline | 复杂迭代，事件回顾 | 时间线清晰，全面 | 时间较长 |

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 回顾报告 | 文档 | 项目文档库 |
| 改进项列表 | 文档 | 项目文档库 |
| Action Items | 任务 | 任务管理系统 |

## 质量标准

### 会议质量标准
- 全员参与发言
- 心理安全，敢于表达
- 讨论聚焦问题本身
- 产生可执行的改进措施

### 输出物质量标准
- 记录完整准确
- 改进项描述清晰
- Action Items符合SMART原则
- 有明确的负责人和截止时间

## 相关Skill

| Skill | 用途 |
|-------|------|
| retro-facilitator | 回顾会议引导 |
| action-tracker | 改进项跟踪 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 关键人员缺席 | 推迟会议或委托收集意见 |
| 情绪冲突 | 暂停讨论，私下沟通 |
| 改进项过多 | 使用投票确定优先级 |
| 改进项过少 | 引导团队深入思考 |

## 最佳实践

### 会议氛围
- 营造安全环境，鼓励坦诚交流
- Scrum Master保持中立，不评判
- 关注"我们"而非"你"
- 避免指责和防御

### 时间管理
- 严格控制每个环节时间
- 使用计时器
- 讨论偏离时及时引导回来
- 复杂问题可会后深入讨论

### 跟进机制
- 每日站会检查Action Items进度
- 下次回顾首先检查完成情况
- 未完成项需要分析原因
- 建立改进项可视化看板
