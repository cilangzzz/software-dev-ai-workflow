# 流程规范：Sprint0准备

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | Sprint0准备 |
| 所属阶段 | 项目启动阶段 |
| 流程负责人 | 敏捷教练 |
| 前置流程 | 敏捷团队组建 |
| 后置流程 | 迭代规划阶段 |

## 流程目的

初始化项目环境，完成团队磨合，为正式迭代开发做好准备。

## 触发条件

- 敏捷团队已组建
- 团队章程已制定
- Definition of Done已定义

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 敏捷团队章程 | 团队组建 | 必须 |
| Definition of Done | 团队组建 | 必须 |
| 初始Product Backlog | 项目立项 | 必须 |
| 技术栈决策 | 项目立项 | 建议 |

## 执行步骤

### Step 1: 开发环境搭建

- [ ] 搭建代码仓库（Git等）
- [ ] 配置持续集成/持续部署（CI/CD）管道
- [ ] 搭建开发环境
- [ ] 搭建测试环境
- [ ] 配置项目管理工具（Jira/Trello等）

### Step 2: 技术架构初始化

- [ ] 创建项目骨架代码
- [ ] 配置基础框架
- [ ] 集成第三方服务
- [ ] 编写技术文档模板

### Step 3: Product Backlog精化

- [ ] 梳理初始Product Backlog
- [ ] 细化高优先级用户故事
- [ ] 进行初步估算（Story Point）
- [ ] 确保用户故事符合INVEST原则

### Step 4: 团队规范建立

- [ ] 确定代码规范
- [ ] 确定分支管理策略
- [ ] 确定代码评审规范
- [ ] 确定文档编写规范

### Step 5: 团队磨合活动

- [ ] 组织团队破冰活动
- [ ] 进行敏捷培训（如需要）
- [ ] 模拟一次完整迭代
- [ ] 复盘并调整工作方式

### Step 6: Sprint0验收

- [ ] 确认开发环境可用
- [ ] 确认团队具备启动条件
- [ ] 确认Product Backlog就绪
- [ ] 获得启动批准

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 环境配置清单 | 文档 | 项目文档库 |
| 技术架构文档 | 文档 | 项目文档库 |
| 精化的Product Backlog | 文档/工具 | 项目管理工具 |
| 团队规范文档 | 文档 | 项目文档库 |

## 质量标准

- 开发环境完全可用，团队能正常开发
- CI/CD管道已验证可用
- Product Backlog高优先级故事已细化
- 团队成员熟悉敏捷流程
- 团队规范已建立并获得认可

## 相关Skill

| Skill | 用途 |
|-------|------|
| ci-pipeline-assistant | CI/CD管道配置 |
| user-story-generator | 用户故事生成与精化 |
| risk-manager | 风险识别 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 环境搭建受阻 | 升级协调资源，可考虑云环境 |
| 团队不熟悉敏捷 | 安排敏捷培训或引入外部教练 |
| Product Backlog质量不足 | 进行Backlog精化会议（时间盒：2-4小时） |
| 技术债务积累 | 在Backlog中添加技术债务项，优先处理 |

## Sprint0注意事项

| 注意点 | 说明 |
|------|------|
| 时间控制 | Sprint0通常不超过1周，避免过度准备 |
| 范围控制 | 仅做必要准备，不进行功能开发 |
| 团队磨合 | 重视团队协作方式建立 |
| 工具配置 | 确保工具配置支持敏捷流程 |

## Sprint0交付标准

| 标准 | 说明 |
|------|------|
| 环境就绪 | 开发、测试环境可用 |
| 工具就绪 | 项目管理、CI/CD工具配置完成 |
| Backlog就绪 | 首批迭代Backlog已细化 |
| 团队就绪 | 团队理解敏捷流程并准备开始 |
