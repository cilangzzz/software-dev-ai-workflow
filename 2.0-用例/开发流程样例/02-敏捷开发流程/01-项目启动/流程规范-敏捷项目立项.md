# 流程规范：敏捷项目立项

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 敏捷项目立项 |
| 所属阶段 | 项目启动阶段 |
| 流程负责人 | 产品负责人 |
| 前置流程 | 商业立项审批 |
| 后置流程 | 敏捷团队组建 |

## 流程目的

明确项目愿景、范围和约束条件，为敏捷团队提供清晰的方向和目标。

## 触发条件

- 商业立项已获批准
- 项目预算已确定
- 项目干系人已识别

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 商业立项书 | 商务部门 | 必须 |
| 项目预算 | 财务部门 | 必须 |
| 干系人名单 | 项目管理 | 必须 |
| 业务需求概述 | 业务部门 | 建议 |

## 执行步骤

### Step 1: 项目愿景定义

- [ ] 明确项目商业目标
- [ ] 定义项目成功标准
- [ ] 确定项目范围边界
- [ ] 识别关键干系人

### Step 2: Product Backlog初始化

- [ ] 收集初始需求
- [ ] 编写用户故事（User Story）
- [ ] 对用户故事进行优先级排序
- [ ] 创建初始Product Backlog

### Step 3: 约束条件确认

- [ ] 确认项目时间约束
- [ ] 确认项目预算约束
- [ ] 确认资源约束
- [ ] 识别技术约束

### Step 4: 项目愿景文档编写

- [ ] 编写项目愿景文档
- [ ] 与干系人确认愿景
- [ ] 获取干系人签字认可

### Step 5: 项目启动评审

- [ ] 组织项目启动评审会
- [ ] 确认项目范围和目标
- [ ] 明确后续行动项

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 项目愿景文档 | 文档 | 项目文档库 |
| 初始Product Backlog | 文档/工具 | 项目管理工具 |
| 干系人登记表 | 表格 | 项目文档库 |

## 质量标准

- 项目愿景清晰明确，获得干系人共识
- Product Backlog包含至少首批10-20个用户故事
- 用户故事符合INVEST原则（Independent, Negotiable, Valuable, Estimable, Small, Testable）
- 约束条件已明确记录

## 相关Skill

| Skill | 用途 |
|-------|------|
| requirement-analyzer | 需求分析，创建Product Backlog |
| milestone-tracker | 里程碑规划 |
| risk-manager | 风险识别 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 愿景不清晰 | 组织愿景工作坊，与干系人共同明确 |
| 需求范围过大 | 进行MVP范围定义，优先核心功能 |
| 干系人意见分歧 | 升级至高层决策者，寻求仲裁 |
| 资源约束过紧 | 调整项目范围或时间线，与干系人协商 |
