# 敏捷质量门控体系

## 概述

敏捷质量门控采用轻量化检查方式，在关键节点进行快速质量验证，确保持续交付质量。

## 质量门控设计原则

| 原则 | 说明 |
|------|------|
| 轻量化 | 检查项简洁，不阻碍敏捷速度 |
| 自动化 | 尽可能自动化验证 |
| 团队内控 | 团队自检而非外部审核 |
| 适度严格 | P0必须通过，P1条件通过 |

## 三层质量门控

### Gate 1: Sprint Ready Gate（迭代就绪门控）

**触发时机**: 迭代规划完成后，迭代开始前

| 检查项 | 级别 | 验证方式 |
|--------|------|---------|
| Sprint Backlog已定义 | P0 | 人工确认 |
| 迭代目标已明确 | P0 | 人工确认 |
| 用户故事已拆分 | P0 | 人工确认 |
| 故事点已估算 | P0 | 人工确认 |
| 团队容量已评估 | P1 | 人工确认 |

**通过标准**: 所有P0项完成

**责任人**: 产品经理、Scrum Master

### Gate 2: Story Done Gate（故事完成门控）

**触发时机**: 每个用户故事开发完成时

| 检查项 | 级别 | 验证方式 |
|--------|------|---------|
| 功能验收通过 | P0 | 产品经理验收 |
| 单元测试通过 | P0 | CI自动化 |
| 代码审查完成 | P0 | 人工审查 |
| 无阻断缺陷 | P0 | 测试验证 |
| 代码已提交 | P0 | CI自动化 |

**通过标准**: 所有P0项完成

**责任人**: 研发工程师

### Gate 3: Release Gate（发布门控）

**触发时机**: 发布前

| 检查项 | 级别 | 验证方式 |
|--------|------|---------|
| 回归测试通过 | P0 | 自动化测试 |
| 安全扫描通过 | P0 | 自动化扫描 |
| 发布说明就绪 | P0 | 人工确认 |
| CI/CD流水线就绪 | P0 | 自动化验证 |
| 回滚预案就绪 | P1 | 人工确认 |

**通过标准**: 所有P0项完成

**责任人**: 运维工程师

## 门控执行流程

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  Sprint Ready    │     │   Story Done     │     │    Release       │
│     Gate         │     │     Gate         │     │     Gate         │
│   (迭代就绪)     │     │   (故事完成)     │     │    (发布前)      │
└──────────────────┘     └──────────────────┘     └──────────────────┘
         │                        │                        │
         │                        │                        │
         ▼                        ▼                        ▼
    ┌─────────┐              ┌─────────┐              ┌─────────┐
    │ P0检查  │              │ P0检查  │              │ P0检查  │
    │ 全通过? │              │ 全通过? │              │ 全通过? │
    └─────────┘              └─────────┘              └─────────┘
         │                        │                        │
    ┌────┴────┐              ┌────┴────┐              ┌────┴────┐
    │         │              │         │              │         │
   Yes       No             Yes       No             Yes       No
    │         │              │         │              │         │
    ▼         ▼              ▼         ▼              ▼         ▼
  进入      延迟          标记      继续         发布      黶迟
  迭代      迭代          完成      开发                  发布
            规划                    (修复)
```

## 与瀑布质量门控对比

| 对比项 | 瀑布质量门控 | 敏捷质量门控 |
|--------|-------------|-------------|
| 门控数量 | 5个（Gate 1-5） | 3个 |
| 检查粒度 | 阶段级别 | 故事级别 |
| 检查频率 | 阶段末 | 每故事/每发布 |
| 文档要求 | 完整文档 | 轻量文档 |
| 自动化程度 | 部分 | 高度自动化 |

## 门控异常处理

| 异常 | 处理方式 |
|------|---------|
| P0未通过 | 阻断进入下一阶段，必须修复 |
| P1未通过 | 记录风险，可条件进入 |
| 多次未通过 | 迭代回顾专项分析 |
