# 数据阶段

## 阶段概述

| 属性 | 值 |
|------|-----|
| 阶段名称 | 数据阶段 |
| 阶段编号 | 09 |
| 主要负责部门 | 数据部 |
| 前置条件 | 系统运行产生数据 |
| 后置阶段 | - |

## 阶段目标

确保数据质量、血缘追溯和数据治理规范落地。

## 关键活动

| 活动 | 说明 | 负责人 |
|------|------|--------|
| 数据质量检查 | 检查数据完整性、准确性 | 数据工程师 |
| 数据血缘追溯 | 梳理数据流转关系 | 数据工程师 |
| 数据治理 | 数据标准化、元数据管理 | 数据工程师 |

## 产出物

| 产出物 | 类型 | 必要性 |
|--------|------|--------|
| 数据质量报告 | 报告 | 必须 |
| 数据血缘图 | 图表 | 必须 |
| 数据字典 | 文档 | 建议 |
| 元数据管理文档 | 文档 | 建议 |

## 详细产出物清单

详见：[产出物清单.md](产出物清单.md)

## 执行时机

数据阶段为跨阶段流程，可在以下时机执行：
- 设计阶段：参与数据模型设计评审
- 开发阶段：参与数据库变更审核
- 运维阶段：定期数据质量检查

## 相关Skill

| Skill | 用途 |
|-------|------|
| data-quality-check | 数据质量检查 |
| data-lineage-trace | 数据血缘追溯 |

## 协作关系

### 输入来源
- 数据库设计文档（设计阶段）
- 数据迁移脚本（开发阶段）
- 运行数据（运维阶段）

### 输出去向
- 数据质量报告 → 运维阶段（数据问题处理）
- 数据血缘图 → 产品阶段（数据理解）
