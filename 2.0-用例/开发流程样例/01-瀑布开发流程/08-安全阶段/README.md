# 安全阶段

## 阶段概述

| 属性 | 值 |
|------|-----|
| 阶段名称 | 安全阶段 |
| 阶段编号 | 08 |
| 主要负责部门 | 安全部 |
| 前置条件 | 开发阶段完成代码提交 |
| 后置阶段 | - |

## 阶段目标

识别和修复安全漏洞，确保系统符合安全合规要求。

## 关键活动

| 活动 | 说明 | 负责人 |
|------|------|--------|
| 威胁建模 | 分析系统安全威胁 | 安全工程师 |
| 安全审计 | 检查系统安全配置 | 安全工程师 |
| 漏洞扫描 | 自动化安全扫描 | 安全工程师 |
| 渗透测试 | 模拟攻击测试 | 安全工程师 |

## 执行时机

安全阶段为跨阶段流程，可在以下时机执行：
- 设计阶段完成后：进行威胁建模
- 开发阶段完成后：进行代码安全扫描
- 测试阶段完成后：进行渗透测试
- 部署前：进行安全合规检查

## 协作关系

### 输入来源
- 架构设计文档（设计阶段）
- 源代码（开发阶段）
- 系统配置（运维阶段）

### 输出去向
- 安全报告 → 开发阶段（漏洞修复）
- 合规报告 → 项目管理阶段（合规证明）
