# 目录结构设计说明

## 概述

本文档定义了 `1.0-软件开发流程角色agent模型` 目录的结构，明确区分 **Agent角色** 和 **Skill技能** 两种不同类型的定义文件。

## 核心概念

### Agent角色 vs Skill技能

| 概念 | 定义 | 文件后缀 | 目录位置 |
|------|------|----------|----------|
| **Agent角色** | 承担特定职责的智能实体，有完整的职责定义、协作关系、质量标准 | `.role.md` 或 `.agent.md` | `agent/` |
| **Skill技能** | 可被调用的具体能力，有明确的输入输出、工作流程、模板 | `.skill.md` | `skill/` |

### 关系模型

```
Agent（角色） ──调用──> Skill（技能）
    │
    ├── 一个 Agent 可调用多个 Skill
    ├── 一个 Skill 可被多个 Agent 共享
    └── Agent 定义"谁来做"，Skill 定义"怎么做"
```

## 文件格式规范

### 统一使用 Markdown 格式

所有 Agent 和 Skill 定义文件统一使用 `.md` 格式，便于阅读和编辑。

### Agent角色定义文件 (`.role.md` 或 `.agent.md`)

```markdown
# 架构师

## 基本信息

- **ID**: architect
- **名称**: 系统架构师
- **版本**: 2.0.0
- **部门**: 研发部
- **描述**: 负责系统整体架构设计、技术选型决策

## 角色定义

### 职责

- 负责系统整体架构设计
- 制定技术选型决策
- 编写架构设计文档和ADR

### 权限

- 技术选型决策权
- 架构评审否决权

### 协作关系

- **上游**: 产品经理
- **下游**: 后端开发、前端开发

## 可调用的技能

| 技能ID | 必需 | 熟练度 |
|--------|------|--------|
| system-architect | 是 | 专家 |
| adr-writer | 是 | 专家 |
| tech-selector | 是 | 专家 |

## 触发条件

- **命令**: `/architect`, `/架构设计`
- **关键词**: 架构设计, 系统架构, 技术架构
- **事件**: requirement-approved

## 质量标准

- 架构设计需通过技术评审
- 关键决策100%有ADR记录
```

### Skill技能定义文件 (`.skill.md`)

```markdown
# 系统架构设计

## 基本信息

- **ID**: system-architect
- **名称**: 系统架构设计
- **版本**: 2.0.0
- **分类**: design
- **描述**: 采用C4模型进行系统架构设计

## 触发条件

- **命令**: `/architect`
- **关键词**: 架构设计, 系统架构

## 输入参数

| 参数名 | 类型 | 必需 | 描述 |
|--------|------|------|------|
| prd_document | string | 是 | PRD文档路径 |
| architecture_type | string | 否 | 架构类型（默认auto） |

## 工作流程

### 阶段1: 需求理解

- 解析PRD文档
- 提取功能需求、性能需求

### 阶段2: 架构决策

- 架构风格选择
- 技术选型
- ADR编写

### 阶段3: 架构设计

- C4 Context层设计
- C4 Container层设计
- C4 Component层设计

## 输出产物

| 产物名称 | 格式 | 必需 | 条件 |
|----------|------|------|------|
| 架构设计文档 | markdown | 是 | - |
| C4架构图 | drawio | 是 | - |
| ADR决策记录 | markdown | 是 | - |
| 风险评估矩阵 | excel | 否 | 大型项目 |

## 质量检查

### 设计前

- [ ] PRD已评审通过
- [ ] 约束条件已明确

### 设计中

- [ ] 架构风格已评估
- [ ] ADR已编写
- [ ] C4模型完整

### 设计后

- [ ] 质量属性满足需求
- [ ] 架构评审通过
```

## 产出物清单规范

### 条件化产出物

产出物清单增加 `条件` 字段，明确特定情况才需要：

| 产出物 | 优先级 | 必需条件 | 说明 |
|--------|--------|----------|------|
| 架构设计文档 | P0 | 始终必需 | 所有项目 |
| ADR决策记录 | P0 | 有关键决策 | 至少1条ADR |
| 风险评估矩阵 | P1 | 大型项目 | 项目周期>3个月或团队>5人 |
| 数据流图 | P1 | 复杂系统 | 涉及多个数据源/目标 |
| C4 Level 4代码图 | P2 | 核心复杂模块 | 核心业务逻辑复杂时 |

## 命名规范

### 目录命名

| 目录 | 说明 |
|------|------|
| `agent/` | Agent角色定义目录 |
| `skill/` | Skill技能定义目录 |
| `references/` | 参考模板目录 |

### 文件命名

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| Agent角色 | `{角色ID}.role.md` 或 `{角色ID}.agent.md` | `architect.agent.md`, `backend-developer.role.md` |
| Skill技能 | `{技能ID}.skill.md` | `code-review.skill.md` |
| 参考文档 | `{模板名称}-template.md` | `prd-template.md` |
