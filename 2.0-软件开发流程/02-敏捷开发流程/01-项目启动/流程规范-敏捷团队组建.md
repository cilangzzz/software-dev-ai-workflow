# 流程规范：敏捷团队组建

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 敏捷团队组建 |
| 所属阶段 | 项目启动阶段 |
| 流程负责人 | 敏捷教练/项目经理 |
| 前置流程 | 敏捷项目立项 |
| 后置流程 | Sprint0准备 |

## 流程目的

组建跨职能、自组织的敏捷团队，明确团队角色和职责，建立团队工作协议。

## 触发条件

- 项目愿景文档已完成
- 初始Product Backlog已创建
- 项目资源已分配

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 项目愿景文档 | 项目立项 | 必须 |
| 干系人登记表 | 项目立项 | 必须 |
| 资源分配计划 | 人力资源 | 必须 |
| 技能矩阵模板 | 组织资产 | 建议 |

## 执行步骤

### Step 1: 团队角色定义

- [ ] 确定产品负责人（Product Owner）
- [ ] 确定敏捷教练（Scrum Master）
- [ ] 确定开发团队成员
- [ ] 明确各角色职责

### Step 2: 团队成员选拔

- [ ] 评估所需技能组合
- [ ] 识别候选成员
- [ ] 进行成员选拔
- [ ] 确认成员可用性

### Step 3: 团队章程制定

- [ ] 定义团队价值观
- [ ] 确定工作方式
- [ ] 明确沟通机制
- [ ] 建立决策规则

### Step 4: Definition of Done定义

- [ ] 定义代码完成标准
- [ ] 定义测试完成标准
- [ ] 定义文档完成标准
- [ ] 定义发布完成标准

### Step 5: 工作协议建立

- [ ] 确定每日站会时间（时间盒：15分钟）
- [ ] 确定迭代周期长度（1-4周）
- [ ] 确定会议时间安排
- [ ] 建立信息同步机制

### Step 6: 团队启动会议

- [ ] 组织团队启动会
- [ ] 分享项目愿景
- [ ] 讲解团队章程
- [ ] 确认工作协议

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 敏捷团队章程 | 文档 | 项目文档库 |
| Definition of Done | 文档 | 项目文档库 |
| 工作协议 | 文档 | 项目文档库 |
| 团队成员名单 | 表格 | 项目文档库 |

## 质量标准

- 团队具备跨职能能力，能独立完成迭代目标
- 角色职责清晰，无重叠或空白
- 工作协议获得全员认可
- Definition of Done标准明确可执行

## 相关Skill

| Skill | 用途 |
|-------|------|
| workload-analyzer | 团队工作量分析 |
| milestone-tracker | 团队目标跟踪 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 关键角色缺失 | 协调资源，或明确临时替代方案 |
| 团队成员技能不足 | 安排培训，或引入外部支持 |
| 成员时间冲突 | 调整成员分配，确保团队稳定性 |
| 远程团队协作 | 建立远程协作协议和工具支持 |

## 敏捷团队角色职责

| 角色 | 职责 |
|------|------|
| 产品负责人（PO） | 管理Product Backlog，确定优先级，代表干系人利益 |
| 敏捷教练（SM） | 促进敏捷实践，移除障碍，保护团队 |
| 开发团队 | 自组织完成迭代目标，交付增量产品 |

## 会议时间盒

| 会议 | 频率 | 时间盒 |
|------|------|--------|
| 每日站会 | 每日 | 15分钟 |
| 迭代计划会议 | 每迭代开始 | 2-4小时 |
| 迭代评审会议 | 每迭代结束 | 1小时 |
| 迭代回顾会议 | 每迭代结束 | 1小时 |
