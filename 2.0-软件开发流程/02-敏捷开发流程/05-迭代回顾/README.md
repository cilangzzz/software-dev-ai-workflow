# 迭代回顾

## 阶段概述

| 属性 | 值 |
|------|-----|
| 阶段名称 | 迭代回顾 |
| 阶段编号 | 05 |
| 主要负责部门 | Scrum团队 |
| 前置条件 | 迭代评审完成 |
| 后置阶段 | 发布交付（如需）或下一迭代规划 |

## 阶段目标

通过回顾会议识别改进项，推动团队持续改进，提升迭代效率和质量。

## 关键活动

| 活动 | 说明 | 负责人 |
|------|------|--------|
| 回顾会议 | 召开Sprint回顾会议 | Scrum Master |
| 改进项识别 | 识别需要改进的问题 | 全体团队 |
| 改进措施落地 | 制定并落实改进措施 | 改进负责人 |

## 产出物

| 产出物 | 类型 | 必要性 |
|--------|------|--------|
| 回顾报告 | 文档 | 必须 |
| 改进项列表 | 文档 | 必须 |
| Action Items | 任务 | 必须 |

## 敏捷价值观体现

| 价值观 | 本阶段体现 |
|--------|-----------|
| 个体和互动 | 全员参与回顾，鼓励开放对话 |
| 响应变化 | 识别改进机会，快速调整 |
| 持续改进 | 核心目标：每迭代比上一迭代更好 |
| 团队自组织 | 改进项由团队自主选择和推动 |

## 常见回顾格式

| 格式 | 适用场景 | 时间 |
|------|---------|------|
| Start-Stop-Continue | 快速回顾 | 30min |
| 4Ls | 深度反思 | 45min |
| Mad-Sad-Glad | 情绪导向 | 60min |
| Sailboat | 长期项目 | 60min |
