# 流程规范：迭代演示

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 迭代演示 |
| 流程编号 | SR-04-01 |
| 所属阶段 | 迭代评审阶段 |
| 执行频率 | 每迭代结束 |
| 时间限制 | 不超过1小时 |
| 参与角色 | 产品经理、研发团队、客户/Stakeholder |

## 流程目的

展示迭代完成的功能，让客户/Stakeholder了解进展，收集反馈。

## 触发条件

- 迭代执行阶段完成
- 所有承诺故事已开发完成或明确未完成原因

## 输入物

| 输入物 | 来源 | 说明 |
|--------|------|------|
| Sprint Backlog | 迭代规划阶段 | 本迭代承诺的故事 |
| 完成的用户故事 | 迭代执行阶段 | 已通过验收的故事 |

## 执行步骤

### 准备阶段
- [ ] 确认演示环境和数据准备就绪
- [ ] 准备演示脚本/流程
- [ ] 通知参与人员

### 演示阶段
- [ ] 产品经理开场，回顾迭代目标（5分钟）
- [ ] 研发团队逐个演示完成的用户故事（40分钟）
- [ ] 记录客户反馈（全程）
- [ ] 说明未完成故事原因（10分钟）

### 收尾阶段
- [ ] 确认验收签字
- [ ] 整理反馈记录

## 输出物

| 输出物 | 说明 |
|--------|------|
| 演示成果记录 | 演示的功能清单 |
| 客户反馈记录 | 收集的意见 |

## 质量标准

| 标准 | 要求 |
|------|------|
| 时间控制 | 会议不超过1小时 |
| 演示完整性 | 所有P0故事必须演示 |
