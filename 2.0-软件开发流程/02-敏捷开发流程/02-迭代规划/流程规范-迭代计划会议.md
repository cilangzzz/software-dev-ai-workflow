# 流程规范：迭代计划会议

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 迭代计划会议 |
| 所属阶段 | 迭代规划阶段 |
| 流程负责人 | 敏捷教练 |
| 前置流程 | 需求梳理 |
| 后置流程 | 迭代执行 |

## 流程目的

确定当前迭代要完成的工作内容，制定迭代目标，分配任务，为迭代执行做准备。

## 触发条件

- Product Backlog已精化
- 高优先级用户故事已细化
- 团队速率已知

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 精化的Product Backlog | 需求梳理 | 必须 |
| 团队速率 | 历史迭代 | 必须 |
| Definition of Done | 项目启动 | 必须 |
| 迭代日历 | 项目管理 | 建议 |

## 执行步骤

### Step 1: 会议准备（会前）

- [ ] 确认会议时间和参与者
- [ ] 准备精化的Product Backlog
- [ ] 准备团队速率数据
- [ ] 准备会议室或远程会议链接

### Step 2: 迭代目标确定（时间盒：30分钟）

- [ ] 产品负责人介绍迭代目标
- [ ] 团队讨论目标可行性
- [ ] 确定迭代目标（Sprint Goal）
- [ ] 记录迭代目标

### Step 3: 用户故事选择（时间盒：30-60分钟）

- [ ] 产品负责人讲解高优先级用户故事
- [ ] 团队提问和澄清
- [ ] 确认验收标准
- [ ] 选择符合团队速率的用户故事

### Step 4: 任务拆分（时间盒：60-90分钟）

- [ ] 将用户故事拆分为具体任务
- [ ] 估算任务工时（理想人时）
- [ ] 识别任务依赖关系
- [ ] 分配任务负责人

### Step 5: 迭代计划确认（时间盒：15-30分钟）

- [ ] 汇总迭代工作量
- [ ] 确认不超过团队速率
- [ ] 确认Sprint Backlog
- [ ] 团队承诺迭代目标

### Step 6: 会议总结

- [ ] 记录会议决议
- [ ] 确认后续行动项
- [ ] 更新Sprint Backlog
- [ ] 通知相关干系人

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| Sprint Backlog | 文档/工具 | 项目管理工具 |
| 迭代目标 | 文档 | 项目管理工具 |
| 任务清单 | 文档/工具 | 项目管理工具 |
| 迭代计划会议纪要 | 文档 | 项目文档库 |

## 质量标准

- 迭代目标清晰明确
- Sprint Backlog工作量不超过团队速率
- 每个用户故事有明确的验收标准
- 团队成员理解并承诺完成迭代目标

## 相关Skill

| Skill | 用途 |
|-------|------|
| milestone-tracker | 迭代目标跟踪 |
| workload-analyzer | 工作量分析 |
| user-story-generator | 用户故事拆分 |

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 故事超出团队速率 | 调整故事范围或移至下个迭代 |
| 验收标准不清晰 | 现场澄清，必要时重新精化 |
| 团队成员不可用 | 调整迭代容量 |
| 依赖关系阻塞 | 标记风险，制定应对计划 |

## 会议时间盒

| 阶段 | 时间盒 | 说明 |
|------|--------|------|
| 迭代目标确定 | 30分钟 | 产品负责人主导 |
| 用户故事选择 | 30-60分钟 | 团队讨论 |
| 任务拆分 | 60-90分钟 | 团队协作 |
| 迭代计划确认 | 15-30分钟 | 团队承诺 |
| **总计** | **2-4小时** | 根据团队规模调整 |

## 迭代计划会议检查点

| 检查点 | 说明 |
|------|------|
| 目标对齐 | 团队理解并认同迭代目标 |
| 容量确认 | 迭代工作量在团队能力范围内 |
| 依赖识别 | 关键依赖已识别并有应对计划 |
| 承诺确认 | 团队明确承诺完成迭代目标 |

## 参与者

| 角色 | 职责 |
|------|------|
| 产品负责人 | 讲解需求，确定优先级，澄清问题 |
| 敏捷教练 | 引导会议，确保流程正确 |
| 开发团队 | 提问、估算、拆分任务、承诺目标 |
