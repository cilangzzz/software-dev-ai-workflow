# 流程规范：每日站会

## 基本信息

| 属性 | 值 |
|------|-----|
| 流程名称 | 每日站会 |
| 所属阶段 | 迭代执行 |
| 流程负责人 | Scrum Master |
| 前置流程 | 迭代规划 |
| 时间盒 | 15分钟 |

## 流程目的

团队成员同步工作进展，发现和解决阻碍，保持团队信息透明。

## 触发条件

- 每个工作日固定时间
- 迭代执行期间
- 全体团队成员参与

## 输入物

| 输入物 | 来源 | 必要性 |
|--------|------|--------|
| 任务看板 | 迭代执行 | 必须 |
| 昨日进展 | 个人工作 | 必须 |
| 今日计划 | 个人工作 | 必须 |

## 执行步骤

### Step 1: 会前准备

- [ ] 更新任务看板状态
- [ ] 准备三个问题的答案
- [ ] 识别需要讨论的问题

### Step 2: 团队集合

- [ ] 围绕任务看板站立
- [ ] Scrum Master 开场
- [ ] 确认时间盒开始

### Step 3: 依次发言

每人回答三个问题：

#### 问题一：昨天完成了什么？

- [ ] 说明完成的任务
- [ ] 更新任务看板状态
- [ ] 简要说明成果

#### 问题二：今天计划做什么？

- [ ] 说明计划任务
- [ ] 预估工作量
- [ ] 更新任务看板

#### 问题三：有什么阻碍？

- [ ] 说明遇到的困难
- [ ] 提出需要的帮助
- [ ] 记录阻塞问题

### Step 4: 问题记录

- [ ] Scrum Master 记录阻碍
- [ ] 标记需要跟进的问题
- [ ] 安排会后讨论

### Step 5: 会后跟进

- [ ] 处理记录的问题
- [ ] 组织问题讨论会议
- [ ] 跟进问题解决进度

## 输出物

| 输出物 | 格式 | 存放位置 |
|--------|------|---------|
| 阻碍问题列表 | 文档 | 项目管理工具 |
| 任务看板更新 | 可视化 | 任务看板 |
| 站会纪要 | 文档 | 会议记录 |

## 质量标准

### 时间控制

- 严格控制在15分钟内
- 每人发言不超过2分钟
- 不进行深入讨论

### 发言规范

- 站立进行，不坐不靠
- 面向任务看板
- 简洁明了

### 问题处理

- 问题及时记录
- 会后专项讨论
- 跟进解决进度

## 禁止行为

### 站会中禁止

- ❌ 深入技术讨论
- ❌ 问题解决讨论
- ❌ 过长的发言
- ❌ 偏离主题

### 应该做的事

- ✅ 记录问题会下讨论
- ✅ 控制发言时间
- ✅ 关注整体进度
- ✅ 及时同步信息

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 人员缺席 | 会后单独同步或异步更新 |
| 超时 | 立即结束，剩余问题会后处理 |
| 争论产生 | 立即打断，安排会后讨论 |
| 发现重大阻碍 | 会后立即组织专项会议 |

## 站会检查清单

### 会前检查

- [ ] 任务看板已更新
- [ ] 燃尽图已更新
- [ ] 定时提醒已设置

### 会中检查

- [ ] 按时开始
- [ ] 时间盒控制
- [ ] 问题已记录

### 会后检查

- [ ] 问题已跟进
- [ ] 看板状态准确
- [ ] 下次站会已安排
