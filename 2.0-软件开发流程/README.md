## 流程模式对比

| 对比项 | 瀑布开发流程 | 敏捷开发流程 |
|--------|-------------|-------------|
| 适用场景 | 需求明确、周期固定的大中型项目 | 需求变化快、需要快速交付的项目 |
| 流程特点 | 阶段顺序执行、文档完整 | 迭代循环、增量交付 |
| 交付方式 | 一次性交付完整产品 | 每个迭代交付可用增量 |
| 文档要求 | 完整文档 | 轻量文档、代码即文档 |
| 质量控制 | 阶段门控(Gate 1~5) | Sprint Ready/Done Gate |
| 核心产出 | PRD、架构文档、测试报告 | Product Backlog、Sprint Backlog |

## 质量门控体系

### 瀑布质量门控

| Gate | 阶段 | 检查项 |
|------|------|--------|
| Gate 1 | 需求阶段 | PRD完整性、用户故事定义、验收标准明确 |
| Gate 2 | 设计阶段 | 设计稿完整性、技术方案评审、数据库设计评审 |
| Gate 3 | 开发阶段 | 代码审查通过、单元测试覆盖率、安全扫描通过 |
| Gate 4 | 测试阶段 | 测试用例覆盖率、缺陷修复率、性能测试通过 |
| Gate 5 | 部署阶段 | 部署方案确认、回滚预案就绪、监控配置完成 |

### 敏捷质量门控

| Gate | 时机 | 检查项 |
|------|------|--------|
| Sprint Ready | 迭代开始 | Sprint Backlog就绪、迭代目标明确、故事已拆分 |
| Story Done | 故事完成 | 功能验收通过、代码审查完成、单元测试通过 |
| Release Gate | 发布前 | 回归测试通过、安全扫描通过、发布说明就绪 |

## 流程执行原则

1. **选择合适流程**: 根据项目特点选择瀑布或敏捷
2. **遵循阶段规范**: 按各阶段流程规范执行
3. **完成质量门控**: 每阶段/迭代必须通过质量门控
4. **持续改进**: 定期复盘优化流程

## 快速入门

### 瀑布流程使用
1. 确定项目阶段 → 查阅对应阶段目录
2. 阅读阶段README → 了解目标、活动、产出物
3. 执行流程规范 → 按步骤完成活动
4. 完成检查清单 → 验证阶段就绪
5. 通过质量门控 → 进入下一阶段

### 敏捷流程使用
1. 项目启动 → 创建Product Backlog、组建团队
2. 迭代规划 → Sprint Planning、拆分故事
3. 迭代执行 → 每日站会、故事开发
4. 迭代评审 → Demo演示、收集反馈
5. 迭代回顾 → 总结改进、制定Action Items
