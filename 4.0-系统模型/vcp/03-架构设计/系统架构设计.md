## 1. 系统概述

VCP（Voice Chat Platform）是一款语音社区平台，采用微服务架构设计，核心业务包括用户管理、服务器/社区管理、频道管理、语音通话、文字消息等模块。

## 3. 服务划分

### 3.1 服务列表

| 服务名称 | 代码 | 职责 | 技术栈 |
|----------|------|------|--------|
| 用户服务 | user-service | 用户注册、登录、资料、好友 | Java/Go |
| 服务器服务 | server-service | 服务器/社区管理、成员、角色 | Java/Go |
| 频道服务 | channel-service | 频道分类、频道管理、权限 | Java/Go |
| 消息服务 | message-service | 文字消息、附件、反应 | Java/Go |
| 语音服务 | voice-service | 语音房间、SFU管理、信令 | Node.js/Go |
| 通知服务 | notify-service | 系统通知、推送、偏好 | Java/Go |
| 审核服务 | moderation-service | 踢人/封禁、举报、敏感词 | Java/Go |
| 搜索服务 | search-service | 消息搜索、用户搜索 | Java/Go |

### 3.2 服务通信方式

| 场景 | 通信方式 | 说明 |
|------|----------|------|
| 同步调用 | REST API / gRPC | 服务间调用 |
| 异步通知 | 消息队列（Kafka） | 事件驱动 |
| 实时推送 | WebSocket | 消息、状态同步 |
| 信令通信 | WebSocket | WebRTC信令 |

## 5. 数据流设计

### 5.1 消息发送流程

```
用户发送消息
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 客户端通过WebSocket发送消息                               │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  2. WebSocket Gateway验证用户身份                            │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Message Service处理消息                                  │
│     - 验证频道权限                                            │
│     - 存储消息到数据库                                        │
│     - 处理@提及                                              │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 发布消息事件到Kafka                                       │
└─────────────────────────────────────────────────────────────┘
    │
    ├──────────────────────────────────────────┐
    ▼                                          ▼
┌───────────────────────┐            ┌───────────────────────┐
│  5a. 推送给在线用户     │            │  5b. 生成通知         │
│  WebSocket Gateway     │            │  Notify Service       │
└───────────────────────┘            └───────────────────────┘
    │                                          │
    ▼                                          ▼
┌───────────────────────┐            ┌───────────────────────┐
│  6a. 客户端收到消息     │            │  6b. 推送通知给@用户   │
└───────────────────────┘            └───────────────────────┘
```

```
用户点击语音频道连接

    ▼

│     - SDP Offer/Answer交换                                   │
│     - ICE候选交换                                           │

    │
    ▼

│  4. 音频流通过SFU路由转发                                     │
│     - 客户端上传音频到SFU                                     │
│     - SFU转发给房间内其他客户端                               │
└─────────────────────────────────────────────────────────────┘
```

## 7. 安全设计

### 7.1 认证授权

| 机制 | 说明 |
|------|------|
| JWT认证 | 用户登录后获取JWT Token，有效期7天 |
| 刷新Token | Token过期前可刷新 |
| 权限校验 | 每个API请求校验用户角色和权限 |
| WebSocket认证 | 连接时验证Token有效性 |

### 7.2 数据安全

| 措施 | 说明 |
|------|------|
| HTTPS | 所有API使用HTTPS加密 |
| 密码加密 | 使用bcrypt加密存储 |
| 敏感数据脱敏 | 日志中不输出敏感信息 |
| SQL注入防护 | 使用参数化查询 |
